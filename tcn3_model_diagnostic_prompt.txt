Context and objective
=====================

TCN3 predicts one signed net-future-excursion score:

    up_points = max future high over horizon - current close
    down_points = current close - min future low over horizon
    target_score = up_points - down_points

The current corrected target metadata is:

    signed_net_future_excursion_points_v1

Do not casually replace this target. It is intentionally designed to measure future directional bias while penalizing adverse excursion. First determine whether the current TCN3 architecture, loss, feature representation, scaling, and training process can learn it. We have spent too much effort optimizing backtest exits before proving forecast quality.

Existing mostly in-sample maximum-history evaluation found approximately:

- Best bounded score similarity around 67%
- Top models around 59-67%
- Correlation around 0.28-0.34
- Most/all top models use label session -1

This is weak for mostly in-sample evaluation and raises the possibility that the model, features, loss, or pipeline is the bottleneck. Your job is to diagnose that rigorously and determine what model/training setup is appropriate for this approach.

Phase 1: audit the pipeline before running experiments
======================================================

Trace the complete path from candle construction to saved checkpoint to evaluator prediction. Verify with small deterministic tests:

- Rolling samples overlap correctly: W candles, then W-1 old candles plus one new candle.
- Target is exactly max-up minus max-down in points for both Python and Numba paths.
- Horizon indexing is t+1 through t+horizon with no off-by-one error.
- Labels and predictions use the same move_scale_points conversion exactly once.
- Training labels are scaled and evaluator predictions are converted back to points correctly.
- Feature channel order and tensor orientation are identical in training, backtest, paper, and evaluator.
- Session filtering selects label endpoints exactly as intended; historical input windows may cross session boundaries.
- Chronological split plus purge has no future-label overlap.
- Invert mode is irrelevant to model accuracy and must not affect predicted score magnitude.

If you find a real pipeline bug, fix it first, add a regression test, clearly mark existing affected model results invalid, and determine whether retraining is required.

Phase 3: establish causal baselines
===================================

Implement and evaluate these baselines on exactly the same eligible indices and chronological splits:

1. Zero prediction.
2. Training-set mean and median constant predictions. Fit constants on train only.
3. Causal persistence: use the most recent excursion label that would be fully known at prediction time. For horizon H, do not use a label until all H future candles needed to calculate it have occurred.
4. Linear or Ridge regression on the same input information. Fit on train only.
5. A small MLP baseline using the same feature inputs and comparable training budget.

Report lift over each baseline for MAE, direction accuracy, correlation, and high-confidence subsets. A complex TCN is not justified unless it reliably beats simple causal baselines out of sample.

Phase 4: capacity/memorization sanity test
==========================================

Run a deliberately small in-sample memorization experiment first, for example:

- AUDUSD
- 5m
- session -1
- window 128
- horizon 5
- approximately 2,000 samples
- dropout 0
- enough epochs to converge, with learning curves saved

Use one fixed sample set. TCN3 should be able to fit this tiny dataset extremely well. Record train loss, score similarity, correlation, R-squared, and prediction/target distributions by epoch.

Interpretation:

- If it memorizes the small set but remains weak on full training history, the relationship is heterogeneous/noisy or the capacity/training objective is insufficient for the full distribution.
- If it fits train but fails chronological holdout, it overfits or the relationship is unstable.

Do not claim success merely because direction accuracy exceeds 50%. Inspect magnitude calibration and baselines.

Phase 6: walk-forward confirmation of finalists
================================================

Take only the small number of configurations that clearly beat baselines. Run multiple chronological folds or expanding-window walk-forward evaluation. Report mean and dispersion across folds, not only one favorable period.

A model is a credible candidate only if:

- It passes the tiny-set capacity test.
- It beats zero, persistence, and linear baselines on purged chronological holdouts.
- Higher abs(predicted_score) generally produces better direction/score accuracy or larger correctly signed realised scores.
- Calibration is not collapsed near zero.
- Results are reasonably consistent across folds/seeds.
- The useful signal is not confined to one tiny subset with too few observations.

Only after those conditions are met should we use the existing TCN3 backtest to study execution.
